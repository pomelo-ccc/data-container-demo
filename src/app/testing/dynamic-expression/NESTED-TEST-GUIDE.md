# 嵌套属性测试指南

## 测试目的

测试 Angular Context 系统中表达式对嵌套属性的依赖追踪和响应式更新能力。

## 测试场景

### 数据结构

```typescript
{
  user: {
    name: '张三',
    age: 30,
    dog: {
      name: '旺财',
      age: 3,
      breed: '金毛',
      color: '金色'
    }
  }
}
```

### 测试组件

#### 父组件 (DynamicExpressionParentComponent)

- 持有 `user` 数据（包含嵌套的 `dog` 对象）
- 提供修改 `user.name`、`user.dog.name`、`user.dog.age`、`user.dog.breed` 的控制
- 显示自己的表达式结果
- 管理子组件的创建和销毁

#### 子组件 (NestedChildComponent)

- 通过表达式访问父级的嵌套数据
- 表达式包括：
  - `${user.name}` - 访问顶层属性
  - `${user.dog.name}` - 访问嵌套属性
  - `${user.dog.age}` - 访问嵌套数值
  - `${user.dog.breed}` - 访问嵌套字符串
  - `${user.name}的${user.dog.name}` - 复合表达式
- 可以修改父级数据
- 拥有本地数据 `localValue`

## 测试要点

### 1. 嵌套属性依赖追踪

**测试步骤：**

1. 添加一个子组件
2. 在父组件中修改 `user.dog.name`
3. 观察子组件的表达式是否自动更新

**预期结果：**

- 子组件中所有访问 `user.dog.name` 的表达式都应该更新
- 复合表达式 `${user.name}的${user.dog.name}` 也应该更新
- 控制台应该显示 Signal 创建日志

### 2. 多个子组件共享数据

**测试步骤：**

1. 添加 3-5 个子组件
2. 在父组件中修改 `user.dog.age`
3. 观察所有子组件是否同步更新

**预期结果：**

- 所有子组件的 `user.dog.age` 表达式都应该显示相同的新值
- 更新应该是即时的，无需手动刷新

### 3. 子组件修改父级数据

**测试步骤：**

1. 添加 2 个子组件
2. 在第一个子组件中修改 `dog.name`
3. 观察第二个子组件和父组件是否更新

**预期结果：**

- 第二个子组件的 `user.dog.name` 表达式应该更新
- 父组件的表达式也应该更新
- 所有组件显示一致的数据

### 4. Signal 清理机制

**测试步骤：**

1. 添加 3 个子组件（观察控制台的创建日志）
2. 点击"移除最后一个"按钮
3. 观察控制台的销毁日志

**预期结果：**
控制台应该显示类似：

```
[Context 销毁] child-1-1234567890 (nested-child)
  - 清理 fieldSelectors: 3 个
  - 清理 expressionDeps: 0 个
  - 清理 store 数据: 1 条
  ✓ 清理完成
```

### 5. 复杂嵌套路径

**测试步骤：**

1. 添加子组件
2. 依次修改：
   - `user.name` → 观察复合表达式
   - `user.dog.name` → 观察复合表达式
   - `user.dog.age` → 观察数值表达式
   - `user.dog.breed` → 观察字符串表达式

**预期结果：**

- 每次修改只影响相关的表达式
- 不相关的表达式不应该重新计算（可通过性能分析验证）

### 6. 本地数据隔离

**测试步骤：**

1. 添加 2 个子组件
2. 在第一个子组件中设置 `localValue`
3. 观察第二个子组件的 `localValue`

**预期结果：**

- 每个子组件的 `localValue` 应该是独立的
- 修改一个不影响另一个

### 7. 批量创建和销毁

**测试步骤：**

1. 快速点击"添加子组件"按钮 10 次
2. 观察控制台日志和页面性能
3. 点击"清空全部"按钮
4. 观察控制台的清理日志

**预期结果：**

- 创建过程应该流畅，无明显卡顿
- 每个子组件都应该有创建日志
- 清空时应该有 10 条销毁日志
- 内存应该被正确释放

## 控制台日志说明

### Signal 创建日志

```
[Signal 创建] child-1-1234567890
  表达式: ${user.dog.name}
  新建 fieldSelector: [user]
  当前 fieldSelectors 总数: 1
```

- 显示哪个组件创建了 Signal
- 显示表达式内容
- 显示新创建的 fieldSelector（用于追踪数据变化）
- 显示当前组件的 fieldSelector 总数

### Context 销毁日志

```
[Context 销毁] child-1-1234567890 (nested-child)
  - 清理 fieldSelectors: 3 个
  - 清理 expressionDeps: 0 个
  - 清理 store 数据: 1 条
  ✓ 清理完成
```

- 显示被销毁的组件 ID 和类型
- 显示清理的资源数量
- 确认清理完成

### 数据修改日志

```
[Parent] 修改 dog.name = 旺财2
[Child #1] 修改 user.name = "李四"
```

- 显示谁修改了什么数据
- 帮助追踪数据流向

## 性能观察

### 使用 Chrome DevTools

1. 打开 Performance 面板
2. 开始录制
3. 执行测试操作（如批量添加/删除子组件）
4. 停止录制
5. 查看：
   - 帧率是否稳定在 60fps
   - 是否有长任务（Long Tasks）
   - 内存是否有泄漏

### 使用 Angular DevTools

1. 打开 Angular DevTools
2. 切换到 Profiler 标签
3. 开始录制
4. 修改父组件数据
5. 停止录制
6. 查看：
   - 哪些组件被重新渲染
   - 变更检测的耗时
   - Signal 的更新路径

## 已知行为

### fieldSelector 复用

- 同一个组件中，多个表达式访问同一个根键（如 `user`）时，会复用同一个 fieldSelector
- 这是性能优化，避免重复创建 Signal

### 表达式缓存

- 表达式的依赖关系会被缓存
- 只有当数据源发生变化时才会重新计算

### 父子数据继承

- 子组件默认继承父组件的所有数据
- 子组件可以覆盖父组件的数据（本地数据优先）
- 子组件可以通过 `getParent()` 直接修改父组件数据

## 故障排查

### 表达式不更新

1. 检查表达式语法是否正确（必须是 `${...}` 格式）
2. 检查数据是否真的被修改（查看控制台日志）
3. 检查是否使用了不可变更新（`{ ...obj, key: newValue }`）

### Signal 未清理

1. 检查组件是否正确销毁（查看控制台销毁日志）
2. 检查是否有循环引用导致内存泄漏
3. 使用 Chrome DevTools 的 Memory 面板检查

### 性能问题

1. 检查是否创建了过多的子组件
2. 检查表达式是否过于复杂
3. 考虑使用 `trackMode: 'explicit'` 限制依赖追踪范围
